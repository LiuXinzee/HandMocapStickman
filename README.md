# HandMocapStickman

一个面向触觉/压力传感器手套的浏览器端手语识别项目。摄像头出的手部骨架只在**训练期**当标注用，部署时只靠一对手套：连续打一句手语，页面整句解码成词序列，再按规则顺成汉语。

> 当前项目属于研究原型。三条链路（孤立词、连续句子、触觉→骨架）都已打通并有已部署的模型权重，但句子模型只见过 90 条真人句子，词表 54 个词、句型表 56 句，**不是能识别任意手语的翻译系统**。下面「当前局限」一节写清了每一条边界。

## 现在能做到什么程度

| 链路 | 输入 | 模型 | 数据 | 指标 |
| --- | --- | --- | --- | --- |
| 连续句子（CTC） | 双手套整句捕获，T=128 | TCN + 逐帧 head + CTC，26 类 + blank | 1770 条（真人 **90** / 合成 1680） | 合成验证集 WER **0.7%** |
| 孤立词（滑窗） | 双手套最近 2000ms，T=32 | TCN + GAP head，27 类（含 `_idle`） | 439 条序列录制 | 验证准确率 **97.7%** |
| 触觉→骨架回归 | 单手 141D 快照 | MLP → 21 关键点 | 单帧样本库 | 见「当前局限」，深度通道是坏的 |

两个模型权重已经在仓库里，clone 下来连上手套就能用：`client/public/models/seq_sentence/`（句子）和 `client/public/models/seq_student/`（孤立词），都是 `python_train/export_weights.py` 的产物。

具体能力：

- **连续模式**：点一次「开始」，之后打完一句自动收句、再起手自动开始，中间不用碰鼠标。收句门限按本句实测的最长停顿自适应（基线 1200ms，上限 3000ms），所以句中犹豫不会把一句切成两半。
- **语法顺句**：手语语序（疑问词句尾、不打「的」、「是」常省）经一张规则表顺成汉语，可开关；规则没命中就原样拼词，不吞词。
- **朗读**：顺句结果走 `window.speechSynthesis`（`zh-CN`），无外部依赖。
- **输出后处理**：拇指/转角速率仲裁易混词、复合词回收、屏蔽词、合并类按句位消解 —— 见「输出后处理链」。
- **自动主手 + 镜像归一**：模型是右手口径训的；只检测到左手时自动按镜像置换归一化，界面上显式提示，不静默做。
- **训练桥**：`/train-sentence` 页面上传数据集、发起 Python 训练、看进度和结果，不用开终端。**只在 `npm run dev` 存在**。
- **手套自检**：`/mocap` 双手 3D 手模（弯折两点标定 + IMU 朝向，不依赖任何模型）、IMU 漂移自检、死通道检测。
- **视觉层**：白手套/黑手套两套判据、左右手互斥约束与成对互换、MediaPipe 资源全本地化（离线可用，CDN 请求 0 次）。

## 快速开始

需要：Node.js 20.19+、pnpm 10（`packageManager` 固定 `pnpm@10.4.1`）、Chrome 或 Edge（Web Serial）。Python 3 只在跑 `python_train/` 时需要。

```bat
corepack enable
corepack prepare pnpm@10.4.1 --activate
pnpm install
pnpm dev
```

终端会打印 `http://localhost:3000/`（端口被占用时 Vite 自动换，以输出为准）。Web Serial 要求 `localhost` 或 HTTPS。

浏览器会**直接占用**所选串口 —— 同一个串口不能同时被其他串口工具、`glove_bridge` 或另一个页面打开。

### 四步流程

页面顶部的 `StepNav` 就是这条路径，每一步都有「下一步去哪」的按钮：

1. **准备** → `/mocap`：连双手套，做弯折两点标定，看 IMU 自检和死通道。**两只手都要标一次** —— 一路弯折传感器坏掉会往 137 维里灌一个常数，训练不报错，只表现为「某几个词就是学不好」。
2. **采集** → `/collect-seq`（孤立词）或 `/collect-sentence`（句子）。`/collect`（单帧静态）现在只喂骨架回归。
3. **训练** → `/train-seq`（孤立词，浏览器内训 + 导出数据集）或 `/train-sentence`（句子，走训练桥调 Python）。
4. **使用** → `/translate`，**不需要摄像头**。

## 数据与特征口径

手套走 Web Serial 直连，921600 波特。包 2 的数据段长度**自动探测**（144B 或 168B，拼合成 272B/296B 帧）—— 写死任一个都会得到「连上了但零帧」。

每帧解析出：256 个原始传感值 → 137 个按物理位置重映射的有效值（60 指压 + 5 弯折 + 72 掌压）、IMU 四元数 `[w,x,y,z]`、以及硬件提供时的加速度和姿态角。

**每手 147 维**（`sequenceFeatures.ts` 与 `python_train/load_dataset.py` 两边必须一致）：

| 区间 | 内容 |
| --- | --- |
| `[0:137]` | 传感点 / 255 |
| `[137:141]` | 相对首帧的四元数 `q₀⁻¹ ⊗ qₜ` |
| `[141:144]` | 重力方向在手系的投影 `R(q)⁻¹·[0,0,1]` |
| `[144:147]` | 加速度 / 16，截断到 [-1,1] |

用相对四元数 + 重力投影而不是绝对朝向：六轴 IMU（ICM-42688，无磁力计）没有绝对 yaw，上电零点是随机的；这两个量对绕重力轴的旋转都不变，所以 yaw 零点照不进特征里。代价是绝对朝向不可用。

| 分支 | 组成 | 维度 |
| --- | --- | --- |
| 学生（部署用，纯触觉） | 147 × 2 手 | **294D/帧** |
| 教师（训练用，融合） | 294 + 归一化关键点 63 × 2 | **420D/帧** |

关键点先减手腕（平移不变）、再按手长（landmark 0→9）缩放，承载手型而非画面位置；手腕点本身保留绝对坐标，承载轨迹。

序列样本在 IndexedDB 里是**列存 TypedArray**（DB v6，`sequences` store），50Hz 栅格，约 64KB/条。行存 `number[]` 会让 600 条撑到 400MB+。视觉缺失帧填 **NaN** 而不是 0（0 是合法坐标）。

`segments: [{label, startFrame, endFrame}]` 一套 schema 同时装孤立词（长度 1）和句子（长度 = 词数），不需要数据库迁移。

> ⚠ 实测这批手套的加速度/姿态角槽位**全零**（见 `rotationRate.ts` 文件头），所以 `[144:147]` 那三维在当前硬件上恒为 0，等于白占。朝向信息只能来自四元数。

## 三条识别链路

### 骨干：TCN

`sequenceModel.ts`（浏览器）与 `python_train/train_seq.py`（Keras）**逐层同构**，这是本仓库一直以来的硬约束。

```
输入 [T, D]
  b1: Conv1D(c1, k=5, same) → BN → ReLU        T
  MaxPool1D(2)                                 T/2
  b2: Conv1D(c1, k=5) → BN → ReLU              T/2
  MaxPool1D(2)                                 T/4
  b3: Conv1D(c2, k=5) → BN → ReLU              T/4
  [可选 backbone="tcn_bigru"] BiGRU(c2/2, returnSequences)
通道数  教师 c1=128 c2=256   学生 c1=64 c2=128
```

时间维只在 head 里塌缩，backbone 输出保持 `(T', C)` —— 孤立词接 GAP，句子接逐帧 head + CTC，换 head 不换骨干。

> 历史坑：这里原本用**空洞卷积**。tfjs 4.22 的 conv2D 前向支持空洞、**反向不支持**，于是模型能建、能 `predict`、`tsc` 和 `build` 全绿，只有真跑 `fit` 才抛错 —— 这一页在浏览器里从来没训练成功过。现在用「小核 + 池化」堆出同样的 32 帧感受野，并有一条「跑一步真 fit」的测试守着。想改回去先跑那条。

### 孤立词（T=32，滑窗）

`/translate` 每 100ms 取最近 2000ms 窗口 → 重采样 T=32 → 预测，靠「连续 N 帧结论相同 + 置信度门限」确认出词。

推理前有一道 **`motionGate`**：分类模型没有「什么都不是」这个选项，而绝大多数窗口里根本没有手语。反直觉的地方是**静止时最容易吐词** —— 手不动时相邻窗口内容几乎一样（结论必然连续相同），恒定输入上的 softmax 又很尖（置信度也过门限），于是「没在打手语」反而是最稳、最自信的误报源。原本指望 `_idle` 伪类接住，但实测数据集里 `_idle` 只有 4 条、中位时长 211ms，对着 2000ms 窗口等于没有这个类。

### 连续句子（T=128，CTC）

时间分辨率是硬约束：骨干池化两次输出 T/4，`T=32` 只有 8 个输出帧，CTC 要求输出帧数 ≥ 标签数（有重复词时 ≥ 2L−1），8 帧连 4 个词都编不稳。所以句子用 `T=128` → 32 个输出帧，约 5 帧/词。**不要靠改池化绕开** —— 改了就和 `sequenceModel.ts` 不同构了。

`blank` 在**末位**（下标 = 类别数）。这个约定错了整句全错，`ctcDecode.test.ts` 里有一条 fixture 断言 JS 解码结果与 Python greedy 逐位一致 —— 那是唯一能抓住两边 blank 约定不一致的测试。

捕获状态机 `idle → armed → capturing → settling`（`sentenceCapture.ts`）：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `SETTLE_MS` | 800ms | 一句一次模式的收句门限 |
| `CONTINUOUS_SETTLE_MS` | 1200ms | 连续模式基线，按本句最长停顿自适应抬高 |
| `SETTLE_CEIL_MS` | 3000ms | 自适应上限 |
| `ARM_TIMEOUT_MS` | 8000ms | 起手超时（连续模式下继续等，不算错误） |
| `MAX_UTTERANCE_MS` | 12000ms | 单句上限，也是环形缓冲长度 |
| `SENTENCE_MOTION_WINDOW_MS` | 600ms | 静止判据的探测窗 |

### 知识蒸馏（两条链路同一套）

```
阶段 1  用带视觉的融合特征训教师
阶段 2  soft = softmax(log(p) / T)      T = 3
        target = α·soft + (1−α)·hard    α = 0.5
        用 target 训学生（输入里没有视觉）
闸门：数据集视觉覆盖 < 80% → 整个教师与蒸馏跳过，学生直接用 hard label
```

`softmax(log(p)/T)` 恒等于对 logits 做温度缩放（`log(pᵢ) = zᵢ − logsumexp(z)`，常数项在 softmax 里抵消）。tfjs 拿不到 logits，这是等价改写，**不要「顺手改回来」**。验证集一律用硬标签：混合标签算出来的 val_acc 衡量的是「像不像教师」，不是「对不对」。

验证集按**整条录制**分组切（`planTrainValSplit` / `split_by_sequence`），且**验证集不做增强**。早先把「原始 + 增强副本」打乱后交给 `validationSplit` 切尾部，等于拿背过的题当考卷 —— 小样本时几乎每条验证行都能在训练集里找到自己的同胞。

### 触觉→骨架回归（旁支）

单手 141D（137 传感 + 4 四元数）→ MLP → `21 × 3 = 63D`，喂 `/mocap` 的 2D 火柴人。

## 输出后处理链

模型解出来的词序列不能直接显示。逐词档和句子档都要过同一批规则（句子档在 `sentencePostprocess.ts` 里统一套用）：

| 模块 | 干什么 | 为什么必须是后处理 |
| --- | --- | --- |
| `labelMerge` | 你/他 合并成 `merged_pron_sg`；我们/你们/他们 合并成 `merged_pron_pl` | 你/他 只差一个绕重力轴的水平角，而六轴 IMU 没有绝对 yaw，**特征层不可分**。「我」已经拆出来了：指自己胸口有真实的压力接触事件，pitch/roll 也不同 |
| `rotationRate` | 用四元数**累计路径转角速率**判「这只手在转没在转」 | 谢谢 = 手不动只压拇指；难过 = 掌心朝胸口画圈。348 个 2000ms 窗上：累计路径转角分对 **97.7%**，首帧起最大转角只有 71.0% |
| `fistGate` | 在谢谢/难过之间仲裁 | 转角速率先定；落在中间带 `[50,70)°/s`（占 16%）或区间短于 1500ms 时才问拇指压力（拇指单独判 88.2%） |
| `compoundWords` | 把拆成两个词的复合词拼回来 | 你好 = 指你 + 竖大拇指，而竖大拇指在纯触觉特征上**就是**「谢谢」。纯触觉模型看不到手在空间里的位置，这两段在当前传感器下不可分 —— 不是训得不够 |
| `suppressedWords` | 纯显示层屏蔽表（当前 `["eat"]`） | 加删一个词不需要重训，也不动任何已存样本。与训练端的 `UNTRAINED_WORDS`（当前 `["happy", "you_pl"]`）是两回事 |
| `sentenceGrammar` | 规则表顺成汉语，并按句位给合并类默认值 | 句首主语位默认「我」、动词后宾语位默认「你」。这是**默认值不是判定** —— 界面上必须能一键换成另外两个，且原始词序一直可见 |

词表：`signLanguageVocab.ts` 54 个词（32 个标了 `dynamic`）。句型表：`sentenceTemplates.ts` 56 句，第一批真人采集 15 句、建议每句 20 条。

> 句型表在 TS 和 Python 各有一份，由 `sentenceTemplates.test.ts` **真的读 `synth_sentences.py` 逐条比对**锁住。早先 `sentenceGrammar.test.ts` 声称能抓跨语言漂移，其实它比的是自己手抄的常量 —— 抓不到。

## Python 训练链路

tfjs 4.22 **既没有 CTC loss 也没有 CTC 解码器**，所以句子级训练只能在本机跑。

```bat
cd python_train
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python train_seq.py --ctc --seq-len 128
.venv\Scripts\python export_weights.py
```

> 本机全局 Python 是共享科研环境，**必须建独立 venv**。根目录那个 `.venv/` 是 `glove_bridge` 的，不是这个。

| 文件 | 作用 |
| --- | --- |
| `export_format.md` | `dataset.bin` + `dataset.json` 的二进制布局 |
| `load_dataset.py` | 读 bin+json → numpy，`is_sentence` = `len(segments) > 1` |
| `synth_sentences.py` | 从孤立词录制交叉淡化拼出合成句子 |
| `train_seq.py` | 与浏览器端同构的 TCN，孤立词 CE / 句子 CTC 两条分支 |
| `export_weights.py` | 导出 `weights.bin` + `weights.json` → `client/public/models/` |
| `export_to_tfjs.py` | `tensorflowjs_converter` 路线（Windows 上走不通，见下） |

**为什么是「只导权重」而不是 `tf.loadLayersModel`**：`tensorflowjs` 的转换器无条件 `import tensorflow_decision_forests`，而 TF-DF 只发 Linux/macOS 轮子；绕过之后还有一关是 tfjs 用的 `tf_keras` 是 Keras 2，读不了 Keras 3 存的 `.keras`。改成浏览器用 `buildSeqSentenceStudent()` 自己搭同构结构再按层名填权重（`modelWeights.ts`）—— 反而更稳：结构不同构会在**加载时**按层名/形状报错并说清是哪一层，而走转换器时同类问题的症状是「加载成功、有置信度、每个词都错」。

**骨干迁移不是可选优化**：句子模型用孤立词学生的同名同形层初始化（只跳过 `*_out`）。CTC 要同时学「是什么词」和「在哪一段」，梯度比分类稀疏得多，随机初始化起跑几百条句子根本训不动。卷积/BN 与输入长度无关，所以 T=32 训的权重直接能用在 T=128 上。

### 训练桥（仅 dev）

`vite-plugin-train-bridge.ts` ↔ `client/src/lib/trainBridge.ts`，把「导出数据集 → 手动拷进 `python_train/data/` → 开终端 → 结果只在 stdout 里」缩成 `/train-sentence` 上的两个按钮。

挂在 `configureServer` 里、`apply: "serve"`，**`vite build` 的产物里一行都没有**。「收文件 + spawn 进程」放进生产服务器就是一个 RCE 面。两道防护缺一不可：请求来源必须是回环，且必须带本次启动生成的随机 token（`transformIndexHtml` 注进页面）—— 因为 `server.host: true`，dev server 监听 0.0.0.0，同网段任何人都能打到这些路由。参数走白名单 + 数值校验，`argv` 数组交给 `spawn`（`shell: false`），请求体里的字符串一个都不进命令行。

## 时间包络：采集和推理必须同源

这是整个项目最容易做错、且错了看不出来的地方。

一条句子样本的时间包络由三处协同决定：起点 = `armed` 状态下**第一次判到 `moving`** 的那一刻（不是按按钮那一刻）；终点 = 砍掉尾部实测的静止；取数 = `snapshotAll(captureSpanMs(act), label, settleDropMs(act))`。

后两个参数**必须成对传**。缓冲区间是贴着尾部对齐的，只调小 span 砍掉的是句子**开头**那几个词，尾部静止照样留着。这是个能编译、能跑、结果看着正常的错误。

所有样本最终都被重采样到定长 T，所以采集端多录进去的一段静止会把每个词在归一化时间轴上的位置整体挪位 —— 合成/真实验证集都看不出来，只有戴上手套才发现打什么都不准。**所以 `/translate` 和 `/collect-sentence` 共用 `sentenceEnvelope.ts` 同一个模块**，包络是构造上相同的，不是约定上相同的。

时间戳一律 `performance.now()`（手套帧时间戳就是它）。混进 `Date.now()` 会让状态机和缓冲相差一个任意常数。

### 起手段裁剪

录制是「按下 → 抬手入画 → 打手势 → 结束」，抬手那 0.5~1.5s 也进了样本，会吃掉时间预算、污染参考帧（相对四元数的首帧变成「手在腿上」）、还可能泄漏。`sequenceTrim.ts` 分两层：

1. **可见性**（`detectSignSpan`）：手在腿上时 MediaPipe 整帧是 NaN，这是最直接的信号。**运动能量在这里恰好是错的判据** —— 抬手本身就是大幅运动，能量比很多手势还高。取双手可见性的**并集**（取交集在单手词上永远为假）、取**最长**连续段（不是第一段）、两端各留 100ms。
2. **到位检测**（`detectArrival`）：可见性在「进入画面」那一刻就翻真，**画面内那段继续上抬它天生看不见**，而那段最难对付 —— 有关键点、能量高、最像手势。判据用手语研究里 transport phase 的标准做法：**速度谷底**，三道门限（必须有明显的谷 / 谷底在前 60% / 要切掉的那段整体是向上冲程）。速度按时间戳算不按帧号。手型经常在抬手途中就捏出来了，所以还有一道**弯折钳位**，方向永远是「少切」。

三条守则：**判不出来就不裁**（六七种 `reason` 各自记下来，宁可留着也不静默切错）；**不写数据库**（只影响特征构建，判据改了重训一次即可，也随时能整体关掉）；**推理端显式不裁**（滑窗是纯触觉，判据不成立，`trim: null` 写在那里是为了说明这件事）。

`/train-sentence` 把每条真实句都画成一根**裁剪条**（`trimStrip.ts`）。硬指标是 `uncoveredRuns`（整段落在保留区间外的可见段数），它必须是 0 —— 第一层取最长可见段，句子中途 MediaPipe 掉一次手就把录制劈成两段、较短那半整段被丢掉（包括第一个词）；45 条真实句里 13 条中招，最坏一条 301 个可见帧只留下 96 个。数字读数看不见这件事（`keptRatio` 0.23 既可能是「两头等太久」也可能是「前 4 秒的动作被扔了」），画成条就一秒可见。

## 换手：左手镜像到右手口径

数据全用右手采，模型就**从没在左手那段槽位上见过任何信号**（特征层给两只手各留一段独立槽位，缺手那段保持全 0），输出塌到某个固定类是必然的。而且 137 维的槽位顺序左右手是**镜像**的。

手语上单手词换手不改词义，所以正解是把左手归一化到右手口径（`handMirror.ts`），**不需要重训**：

- 137 维置换表 `MIRROR_PERM_137` 由规格书网格与同款手套的第三方实现**双向互证**（137 点逐点比对 0 处不一致），且自身满足双射、自逆、手指块仍落手指块、弯折 60~64 → `[64,63,62,61,60]`。手掌是个不规则置换（5×15 减掉 3 格），**手写「反转一下」一定会错**，所以必须是显式表。
- IMU 的镜像是反射共轭 `R' = M R M`（`M = diag(−1,1,1)`）：四元数 `(w,x,y,z) → (w,x,−y,−z)`，真矢量 `(x,y,z) → (−x,y,z)`。只镜像每帧原始四元数就够了，相对四元数和重力投影会自动跟着对。
- 主手不再让用户手选，`dominantHand.ts` 从推理用的同一个滑窗里判：静止的手弯折通道只在噪声底上抖，做手语的手一秒内走掉大半个标定量程。弯折能量除以**这一路两点标定量到的量程**（左右手量程差得很多）。
- 界面上必须显式提示「已按镜像归一化到右手口径」。静默做这件事很危险 —— 识别结果对不上时用户没法分辨是「手语做错了」还是「软件把左手当右手在算」。

⚠ 采集端**不做**镜像。数据集存的必须是原始录制，镜像发生在建特征那一层。存进去的镜像不可逆。

## 视觉层

只在采集/训练期用。`useHandTracking` + MediaPipe Hands，最多两只手、每只 21 个关键点。

- **白手套判据**：实物手套是白色的（规格书写「黑色面料」是错的），而原有三条 `isGlove` 判据每一条都要暗像素。新增一条「亮 + 低彩度」的**或**分支，黑手套的数一个都没动。光靠「亮」完全不够 —— 一面白墙 100% 满足 —— 所以配两道反假阳性闸门：包围盒与外扩环带的亮度差、以及布料纹理的亮度标准差。裸手靠 `warmSkinTone` 排除。
- **白手套一律 `surface="unknown"`**。银点是黑手套掌面的反光标记，白手套整只都是高亮低彩度，硬判掌背只会瞎猜。这不是损失：`surface` 只进显示和元数据，**从不进特征和模型**，朝向靠 IMU。
- **左右手互斥**：两只手同时在画面里，物理上必然一左一右。原来每条 track 各自独立判手别，可以判出两个 `Left`，于是同步录制往 `leftLandmarks` 里写两只手、`rightLandmarks` 全是 NaN —— **训练不报错、能量曲线正常**，只表现为某几个词学不好。现在有冷启动空间顺序定手别、兜底互斥约束、以及**成对**手别交换（两条 track 都连续 30 帧互报对方且 `missedFrames` 都是 0 才换 —— 只提高单条的阈值是没用的，配对状态下单条翻转永远活不下来，真交叉就变成不可恢复）。
- **MediaPipe 资源本地化**：11 个文件在 `client/public/vendor/mediapipe-hands/`，逐字节校对与 CDN 一致。原本运行时要拉约 24MB，离线/CDN 被墙/客户现场演示时初始化失败，而失败的样子像摄像头权限问题。已用 DNS 黑洞 jsdelivr 验证过：本地 vendor 命中 13 次、CDN 请求 0 次。`hands_solution_simd_wasm_bin.data` 是 0 字节但**正常**，官方 CDN 的 `Content-Length` 就是 0，删了会 404。

拍摄建议：均匀光线、与手套反差明显的低纹理背景（白手套优先深灰哑光，避免白墙/白桌面/鼠标与轮廓重叠）。双手先分开进画面再逐渐交叉。侧面、握拳、大面积重叠要当作重点采集场景，不能只采正对摄像头的展开手掌。

## 当前局限

**句子模型**

- 只见过 **90 条真人句子**，另外 1680 条是从孤立词录制交叉淡化拼出来的合成句。合成验证集 WER 0.7% 只说明**管道是对的**，不能预测戴上手套的表现 —— 真实连续手语的协同发音（上一个词还没收手就开始过渡到下一个词）在孤立词录制里结构上不存在。
- 句型表 56 句里只有 15 句有真人数据。`merged_pron_pl`（我们/你们/他们）只有 `we study` 一条真实句型支撑，复数句子应按「还是纯合成」来预期。
- 采集页写进 `segments` 的 `startFrame`/`endFrame` 是**占位值**（每个词都填整段）。CTC 只读标签顺序，这是合法的训练目标，但**别拿它当对齐结果用**。
- 合成句的接缝时长 `overlap_ms = (100, 250)ms` 是**估的**，没有测量支撑。`signTransitions.ts` 就是为了从真人录制量出这个数而写的。

**孤立词模型**

- 27 类里 `_idle` 只有 4 条、中位时长 211ms，等于没有这个类，实际靠 `motionGate` 兜。
- 「你好 vs 谢谢」「好看 vs 像」这类复合词、以及「你/他」，在当前传感器下**特征层不可分**，只能靠后处理规则和默认值。规则表能给出正确的显示，但那不等于模型认出来了。
- `is`（是）是个孤儿类，每次训练都告警。

**硬件与特征**

- 加速度/姿态角那 6 个槽位实测全零，特征里的 3 维加速度恒为 0。
- 六轴 IMU 没有绝对 yaw，上电零点随机。朝向只能用相对量。
- 手套只有弯折 + 压力 + IMU，**没有位置观测**。而手语的位置是语言学通道（额头/下巴/胸前是不同的词）：IMU 给朝向不给位置，加速度二次积分在手上无 ZUPT 可重置。所以任何「看起来像一个人在打手语」的场景里，手的位置只能是常量 —— 这也是 `SigningStage.tsx` 被删掉的原因，它把「位置是编的」藏得更深。
- 陀螺校准是**硬件动作**（短按每只手套主控按键），软件只能检测并指出该按哪只。

**静态链路与骨架回归（都是旧路，留着但别指望）**

- 静态单帧链路（`/train`、`signLanguageModel.ts`）的关键点是 MediaPipe 的**绝对图像坐标**，没做手腕平移与手长归一 —— 教师会把「手在画面哪个位置」当特征学进去再蒸馏给学生。时序链路已绕开，静态链路要修得重训。
- 骨架回归的目标是绝对坐标，而 **z 是以手腕为原点的相对深度、经常为负**，配 sigmoid 输出永远够不到 → **深度通道等于废掉**。2D 火柴人只画 x/y 所以看不出来。要修得改归一化 + 换输出层 + 重训，已存骨架模型全部作废。

**工程**

- 训练桥只在 dev 存在，生产构建里 `/train-sentence` 的控制区禁用。
- 数据和浏览器内训的模型存在当前站点来源的 IndexedDB 里。清站点数据、换浏览器配置、或换协议/主机/端口打开都会导致原数据不可见，**且删了没有撤销**。重要实验一定先在 `/train-seq` 点「导出数据集给 Python」存一份。
- 页面显示的验证准确率来自按录制分组的划分，不是按参与者/按日期划分。跨用户、跨日期、跨环境的真实效果没有测过。

## 数据、模型与隐私

- 采集样本和浏览器内训的模型默认存在当前站点来源的 IndexedDB，不随 Git 提交。
- `client/public/models/` 下的两个模型是**构建产物**，随代码一起部署 —— 换模型要重新部署，不是在页面上点一下。
- 应用没有把摄像头画面、手套数据或模型上传到业务后端的接口。字体、界面图片等资源可能仍从外部 CDN 请求（MediaPipe 已本地化）。
- 开发模式包含本地调试日志收集器，浏览器日志、网络请求和会话调试事件可能写入本机 `.manus-logs/`（已 Git 忽略）。处理敏感参与者数据前先检查并关掉不需要的调试配置。
- `client/index.html` 预留了分析脚本环境变量。公开部署或采集真实参与者数据前，核对实际构建环境是否配置了分析服务，并在知情同意中说明。
- 仓库里的测试视频会随 Git 分发，只提交已确认可以公开的素材。
