# 织物电子皮肤通信协议说明

本文记录矩侨精密织物电子皮肤手套的数据帧格式，以及项目中两种解析方式的兼容范围。

## 数据包结构

每个串口数据包均按以下顺序排列：

```text
[帧头 4B] + [包序号 1B] + [传感器类型 1B] + [数据段]
```

协议没有单独的长度字段或校验字段。第一包长度固定；第二包需要根据候选数据段之后是否紧跟下一帧头，在 144 和 168 字节之间判定。

### 帧头

固定为 4 字节：`0xAA 0x55 0x03 0x99`。

### 包序号

- `0x01`：第一包
- `0x02`：第二包

### 传感器类型

- `0x01`：LH（左手）
- `0x02`：RH（右手）
- `0x03`：LF（左脚）
- `0x04`：RF（右脚）
- `0x05`：WB（全身）

本项目的手套索引重映射仅针对 `0x01` 和 `0x02`。

## 数据段格式

### 第一包

```text
[AA 55 03 99] [01] [传感器类型] [128B 传感器数据]
```

第一包整包长度为 `4 + 1 + 1 + 128 = 134` 字节。

### 第二包：旧版格式

```text
[AA 55 03 99] [02] [传感器类型] [128B 传感器数据] [16B 四元数]
```

第二包数据段为 144 字节，整包长度为 `4 + 1 + 1 + 144 = 150` 字节。第一、二包的数据段拼合后为 272 字节：

| 拼合后偏移  | 长度 | 内容                                          |
| ----------- | ---- | --------------------------------------------- |
| `[0:256]`   | 256B | 原始传感器数据                                |
| `[256:272]` | 16B  | IMU 四元数 `[w, x, y, z]`，四个小端 `float32` |

### 第二包：带加速度的扩展格式

```text
[AA 55 03 99] [02] [传感器类型] [128B 传感器数据] [16B 四元数] [12B 加速度] [12B 姿态角]
```

第二包数据段为 168 字节，整包长度为 `4 + 1 + 1 + 168 = 174` 字节。第一、二包的数据段拼合后为 296 字节：

| 拼合后偏移  | 长度 | 内容                                                      |
| ----------- | ---- | --------------------------------------------------------- |
| `[0:256]`   | 256B | 原始传感器数据                                            |
| `[256:272]` | 16B  | 四元数 `[w, x, y, z]`，四个小端 `float32`                 |
| `[272:284]` | 12B  | 加速度 `[x, y, z]`，三个小端 `float32`                    |
| `[284:296]` | 12B  | 姿态角 `[yaw, roll, pitch]`，单位为度，三个小端 `float32` |

`client/src/lib/gloveProtocol.ts` 和 `glove_bridge/glove_ws_bridge.py` 均支持 144 字节和 168 字节两种第二包格式。Python 桥接器不预设固件版本，而是按串口字节流自动判长。

### 第二包自动判长

Python 桥接器从第二包数据段起点依次检查两个候选边界：

1. 若第 144 字节数据之后的 4 字节为 `AA 55 03 99`，按旧版格式解析。
2. 否则检查第 168 字节数据之后的 4 字节；若为帧头，按扩展格式解析。
3. 缓冲区不足以看到某个候选边界之后的完整 4 字节帧头时，保留当前包并等待下一次串口读取，不提前消费数据。
4. 两个候选边界都不是帧头时，将当前包视为坏帧，清除同一传感器类型尚未配对的第一包，再从后续帧头继续同步。

解析器使用 `bytearray.find` 和游标扫描一轮缓冲区，扫描结束后统一裁剪已消费部分。找不到完整帧头时只保留末尾最多 3 个、可能构成下一个帧头前缀的字节，避免无效数据使缓冲区持续增长。每个 `GloveSerialReader` 实例维护独立的第一包缓存，因此多个串口读取器不会互相配对数据。

## 串口参数

- 波特率：`921600 bps`
- 数据位：8 位
- 校验位：无
- 停止位：1 位

## 传感器数据与索引

两包合并后共有 256 字节原始传感器数据，但每只手只使用其中 137 个有效传感点：

- 60 个手指压力点：每根手指 12 个
- 5 个弯折传感器
- 72 个手掌压力点

规格书中的原始索引从 1 开始，范围为 `1` 至 `256`；JavaScript 数组索引从 0 开始，因此代码读取时必须减 1。例如，规格书索引 `31` 对应 `rawData[30]`。

137 点重映射结果的排列顺序为：

- 左手：小拇指、无名指、中指、食指、大拇指、五个弯折点、手掌 72 点
- 右手：大拇指、食指、中指、无名指、小拇指、五个弯折点、手掌 72 点

具体索引数组见 [sensor_index_notes.md](./sensor_index_notes.md)。浏览器解析器同时保留 `sensor_data`（256 个原始值）和 `mapped_data`（137 个按物理顺序重排的值）；Python WebSocket 桥接服务目前只发送 `sensor_data`。
