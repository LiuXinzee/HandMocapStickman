# 手套传感器索引映射说明

原始数据流包含 256 个传感器字节，但这些字节并未按手指和手掌的物理位置连续排列。项目按照规格书中的索引表，将其中 137 个有效传感点重排为便于显示和训练的物理顺序。

## 索引规则

- 下列映射数组沿用规格书的索引，均从 1 开始，取值范围为 `1` 至 `256`。
- JavaScript 数组索引从 0 开始，读取 `rawData` 时需要将每个规格书索引减 1。
- 例如，规格书索引 `31` 对应 `rawData[30]`。
- 重映射结果共 137 点：60 个手指压力点、5 个弯折点和 72 个手掌压力点。

## 代码中的数据形式

- `sensor_data`：256 个原始传感器值，保持串口字节顺序。
- `mapped_data`：浏览器解析器根据 `sensor_type` 生成的 137 个有效值，已经按上述物理顺序重排。
- `client/src/lib/sensorMapping.ts` 保存实际使用的从 0 开始索引，并由 `remapSensorData` 执行重映射。
- `glove_bridge/glove_ws_bridge.py` 当前只通过 WebSocket 发送 `sensor_data`，不会生成 `mapped_data`。

因此，所谓“线序不对”通常是把 `sensor_data` 直接当作物理顺序显示造成的；需要展示、采集或训练物理传感点时，应使用 `mapped_data`，或在接收端执行同样的 137 点重映射。
